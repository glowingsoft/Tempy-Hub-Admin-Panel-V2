PEEP & Floor Plan — mapped to our project structure

Same feature and rules as the PM's original wireframe, re-laid-out to match our boilerplate: a persistent sidebar shell, list pages with search + filters, detail screens, and add / edit forms. Every screen below is labelled with its structural type. Pin colour is still derived, not stored — it is recomputed each render from the linked resident's current PEEP level.

F1 — Permission boundary table

Line Manager and Platform Super Admin columns are deliberately empty — see the note below.

Note for developers

Why Line Manager and Platform Super Admin have no PEEP screen. Line Manager visibility elsewhere in TempyHub is built on staff hierarchy — their team's rota, leave, compliance. PEEP is a resident-safety feature and residents don't report into a staff hierarchy, so there is no equivalent scope to give this role. There's no defensible slice of residents to show them that isn't already “their whole site”, which is the Site Manager's job.

Platform Super Admin's exclusion is not specific to PEEP — this role never sees resident data of any kind, anywhere in the product, including aggregate counts. That boundary is set at platform level; PEEP inherits it.

Treat both absences as intentional. If either screen shows up in a future backlog, treat it as a bug in the ask, not a gap in this design.

A resident's room number determines which floor's plan their pin lives on — this mapping is implicit, derived from the room, and never assigned a second time when placing a pin. Likewise the pin colour is always derived from the resident's current PEEP level and is never stored.
